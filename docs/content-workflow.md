# Content Workflow

## Manual Writing

Use `/admin` for Decap CMS or edit MDX files directly under `apps/web/src/content`.

Raw notes and logs can be staged under `automation/raw/inbox` before conversion. Keep sensitive files out of Git; use `automation/raw/private` for local-only scratch material.

## Collections

- Projects: systems implementation records.
- Notes: reusable technical references.
- DevOps: operation logs, deployment notes, and runbooks.
- Research: computer science, electrical/electronic engineering, systems engineering, AI infrastructure, software engineering, algorithms, and embedded/system-level engineering notes.
- Paper Reviews: concise reviewed-paper notes with summary, core idea, implementation details, limitations, references, and related work.
- Archive: temporary notes, experiments, and reviewed archive material.

## Drafts

Drafts use:

```yaml
draft: true
reviewed: false
reviewStatus: "needs-review"
```

Drafts are excluded from public routes.

Visibility is controlled only by `draft`.

- `draft: true` is hidden from public listing and detail pages.
- `draft: false` is visible on public listing and detail pages.
- `reviewed`, `autoGenerated`, `generatedAt`, `source`, and `sourceUrl` do not control visibility.
- If an automation-created entry should remain hidden, keep `draft: true`.

## Public Metadata Policy

Internal workflow fields are kept in frontmatter, but public pages must not label posts as generated, manual, reviewed, or in-review.

Public pages may display:

- title
- description
- date
- updated date
- tags
- category
- content type
- source or source URL when useful and non-sensitive

Do not display these workflow fields on public pages:

- `autoGenerated`
- `generatedAt`
- `reviewed`
- `reviewStatus`
- `sourceKind`
- `sensitivity`

Once a draft has been reviewed and published, it should appear as a normal article. `autoGenerated` remains only for internal tracking because a draft may later be substantially edited by hand.

## Generated Draft Metadata

Generated content should normally start unpublished:

```yaml
draft: true
autoGenerated: true
generatedAt: "2026-05-13"
reviewed: false
reviewStatus: "needs-review"
contentType: "deployment-note"
sourceKind: "raw-note"
sensitivity: "sanitized"
source: "source system or workflow"
sourceUrl: "https://example.com/source"
```

## Raw Note To Draft

Use the local generator for a first-pass structure:

```bash
npm run draft:from-note -- --source automation/raw/inbox/example.md --collection devops --type deployment-note --tags "deployment,github-pages"
```

The generator:

- reads one raw note or log file
- redacts obvious IPs, emails, bearer tokens, and key/value secrets
- infers a collection and content type when not supplied
- writes an MDX draft into the existing Astro content collections
- never publishes content

Manual review is still required before changing `draft` or `reviewStatus`.
