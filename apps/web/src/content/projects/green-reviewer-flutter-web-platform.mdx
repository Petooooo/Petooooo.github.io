In September–December 2023, I worked on **Green Reviewer**, a web and mobile application that let users examine products through reviews concerned with misleading environmental claims. The original project was motivated by greenwashing: product marketing could communicate an environmental benefit without giving the consumer an equally clear basis for evaluating it.

I developed the **client, web application and server-side components**, and the original repository still contains the application and server structure. This project is different from my later kernel and infrastructure work, but it remains worth keeping because it records an end-to-end application with a real client/server boundary.

*This retrospective was written in November 2026 from the 2023 project and its publicly available repository. The project date is historical; it is not a claim that this article was published in 2023.*

## A service spanning mobile, web and backend

The client was built with **Flutter and Dart**, while the backend used **Node.js and Express**. The repository separates the client from server-side components and documents a database-facing service as well as a conversion and facade-server arrangement.

The reason for separating these responsibilities was practical: the client handled navigation and displaying product/review information, while the server handled requests, data processing and database access. The same underlying service could support web and mobile clients instead of embedding the database connection in each client.

## Product information, reviews and user experience

The application focused on exposing environmental claims and review information in a way that users could browse and compare. The project description also included links to products or purchases, connecting review data with the user's next action.

That required a coherent contract between presentation and backend data: a page should not need to know how database records are stored, and a backend response should provide enough structure for both web and mobile screens.

## Running the backend as services

The public repository documents a **Docker Compose** path for the server components and a conventional local Flutter workflow for the client. It also contains configuration templates for database, conversion-server and facade-server connections.

Those files show that the system was structured as multiple cooperating processes, rather than only a visual prototype. I kept configuration placeholders in the public repository and do not reproduce private deployment credentials or historical production endpoints here.

The repository also references AWS as part of the original stack. I describe it as a technology used in the project, not as evidence of a specific uptime guarantee or a currently operating public service.

| Layer | Implementation |

The useful part of this project is the **complete application boundary**—a user interface, application server, persistence and a deployable server configuration. I did not treat the original public endpoint as a live availability claim in 2026.

The source remains available at [Green Reviewer on GitHub](https://github.com/Petooooo/green-reviewer). It also provides a concrete starting point for the infrastructure work I later did at a different scale.
