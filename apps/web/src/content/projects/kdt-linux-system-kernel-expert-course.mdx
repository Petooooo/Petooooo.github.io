> **Training record, not a claim of original research.** I completed the K-Digital Training *Linux Systems and Kernel Expert Course*, second cohort, in March 2024. The course began in October 2023. This summary is based on the **official course outline** and my archived, week-by-week training notes, covering roughly 600 recorded sessions. A listed exercise or course project is **not automatically evidence that I independently completed that project**.

## A systems-level curriculum

The course connected user-space development, operating-system behavior, and lower-level debugging rather than treating each tool as a standalone skill.

| Track | Subjects recorded in the syllabus and study notes |
| --- | --- |
| **Programming** | C++ basics, pointers, memory ownership, data structures, algorithms, building/debugging |
| **Linux operations** | Shell, files, permissions, users and groups, services, networking and package management |
| **System programming** | Processes/threads, signals, timers, POSIX shared memory, message queues, mmap, sockets |
| **Kernel internals** | Interrupts, scheduling, runqueues, synchronization, VM, page tables, VFS and filesystem behavior |
| **Hardware interface** | Raspberry Pi, ARM concepts, kernel modules, GPIO/SPI/PWM and device-driver foundations |
| **Container systems** | Docker, Compose, registries, cloud/edge-service concepts |
| **Observability** | ftrace, KernelShark, eBPF/BCC, GDB, crash dumps, Trace32, metrics/logging stacks |

The training progressed from C++ and everyday Linux tools through system calls and user/kernel boundaries, then toward scheduling, virtual memory, storage, drivers and diagnostic workflows.

## What mattered to me

I initially approached systems as someone with both computer-science and electronic-engineering coursework. The course helped me build a conceptual bridge between **C/C++ programs**, the **Linux kernel interfaces they rely on**, and **device/operating-system behavior**.

Of particular interest were **process and thread lifecycles**, **virtual address translation**, **VFS and filesystem metadata**, and **kernel-level tracing**. Later, when I worked on K3s infrastructure, those concepts helped distinguish application behavior from host OS, storage and networking failures.
