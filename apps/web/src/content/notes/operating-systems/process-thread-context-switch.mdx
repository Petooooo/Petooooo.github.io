## 프로세스와 스레드 차이

프로세스는 실행 중인 프로그램의 독립적인 실행 단위다. 각 프로세스는 별도의 주소 공간을 가지며, OS는 프로세스마다 자원과 실행 상태를 관리한다.

스레드는 프로세스 내부의 실행 흐름이다. 같은 프로세스 안의 스레드들은 코드, 데이터, heap 같은 주소 공간을 공유하지만, 각자 stack과 register 상태를 가진다.

## 공유 자원과 독립 자원

| 구분 | 프로세스 | 스레드 |
| --- | --- | --- |
| 주소 공간 | 보통 독립 | 같은 프로세스 내에서 공유 |
| Heap/Data | 독립 | 공유 |
| Stack | 독립 | 스레드별 독립 |
| 파일 디스크립터 | 프로세스 단위 | 같은 프로세스 내에서 공유 가능 |
| 장애 영향 | 다른 프로세스와 격리됨 | 같은 프로세스 전체에 영향 가능 |

## Context Switch에서 저장/복원되는 것

Context switch는 CPU가 실행하던 흐름을 멈추고 다른 흐름으로 전환하기 위해 실행 상태를 저장하고 복원하는 작업이다.

주로 저장/복원되는 정보:

- program counter
- stack pointer
- general-purpose registers
- CPU flags
- address space 관련 정보
- scheduler가 관리하는 실행 상태

## 왜 스레드 전환이 보통 더 가벼운지

스레드 전환은 같은 프로세스 주소 공간 안에서 일어나는 경우가 많다. 따라서 프로세스 전환보다 주소 공간 전환 비용이 작고, TLB/cache 영향도 상대적으로 적을 수 있다.

다만 스레드가 항상 싸다는 뜻은 아니다. lock contention, shared data race, cache line bouncing 같은 문제가 생기면 오히려 성능이 나빠질 수 있다.

## 정리 표

| 항목 | 핵심 |
| --- | --- |
| 프로세스 | 독립 주소 공간을 가진 실행 단위 |
| 스레드 | 프로세스 내부의 실행 흐름 |
| 프로세스 전환 | 주소 공간 전환 비용이 포함될 수 있음 |
| 스레드 전환 | 주소 공간 공유 때문에 보통 더 가벼움 |
| 주의점 | 공유 자원은 동기화가 필요함 |
