2023년 10~11월에는 C와 **Lex/Yacc를 사용해 Python 코드의 Tokenizer와 Syntax Analyzer**를 구현했다. 문자열에서 의미 있는 Token을 찾아내는 일과, 그 Token의 순서가 문법에 맞는지 판단하는 일을 직접 나눠 설계해 본 프로젝트였다.

프로그램이 소스 코드를 이해하려면 문자열을 한꺼번에 읽는 것으로는 부족하다. 같은 문자라도 어떤 위치에 있는지에 따라 키워드가 될 수도 있고 식별자가 될 수도 있으며, 연산자나 문장 구분 기호는 다른 규칙으로 처리해야 한다.

이 글은 당시 2023년 프로젝트 이력을 2026년 11월에 다시 정리한 회고 기록이다.

## 문자열을 Token으로 분리하기

Tokenizer는 소스의 문자들을 읽고 **식별자, 숫자, 키워드, 연산자, 구분 기호**처럼 문법 분석에 필요한 단위로 분리한다.

Lex를 사용하면서 어떤 문자열이 어떤 Token 패턴에 대응하는지 규칙을 정의했다. Token을 반환하는 과정에서 서로 겹치는 패턴을 어떻게 구분할지도 고려해야 했다.

## Lex와 Yacc의 책임 분리

**Lex는 입력 문자열이 무엇인지**, **Yacc는 Token의 조합이 어떤 구문을 이루는지** 처리하도록 역할을 나눴다.

예를 들어 같은 Identifier Token이라도 문법 안에서는 피연산자가 될 수도 있고 할당문의 일부가 될 수도 있다. Lexer에서 문법까지 한꺼번에 처리하려고 하면 입력 규칙과 문장 구조를 수정할 때 서로 영향을 주기 쉽다.

C 프로그램에서 두 생성 도구의 출력을 연결하면서 Token 정의와 Grammar Rule 사이의 일관성을 맞추는 작업이 필요했다.

## 문법에 맞지 않는 입력을 다루기

정상적인 문장만 넣으면 작은 Parser도 쉽게 동작하는 것처럼 보인다. 하지만 예약어와 식별자가 비슷한 경우, 연산자가 이어지는 경우, 문장이 완성되지 않은 경우에는 Lexer와 Parser의 경계가 드러난다.

이 프로젝트에서는 **Python 형태의 입력을 대상으로 Token과 구문을 분석하는 기능**을 구현했다. 현대 Python 언어 사양 전체를 완전히 지원하는 컴파일러라고 소개할 근거는 없으므로, 구현한 범위에 맞춰 Tokenizer와 Syntax Analyzer라고 부른다.

## 구현 결과

C와 Lex/Yacc를 이용해 **소스 입력을 어휘 분석과 구문 분석 단계로 처리하는 프로그램**을 완성했다. 입력 데이터를 구조화된 단위로 바꾸고 그 순서를 해석하는 경험은 이후 문서 처리와 프로토콜 분석에도 연결되는 기초가 됐다.
