2024년 4~5월에는 FPGA에서 **Systolic Array 기반 행렬곱 가속기**를 구현했다. 나중에 진행한 Bit-Shift CNN 가속기보다 앞선 프로젝트로, 여러 Processing Element(PE)에 연산을 분산하고 입력 데이터가 일정한 순서로 흘러가게 만드는 것이 핵심이었다.

행렬곱은 수식만 보면 반복되는 곱셈과 덧셈이지만, FPGA에 올리면 매 클럭 어떤 값이 어디에 있어야 하는지 직접 결정해야 한다. 바로 그 데이터 흐름을 설계하는 과정이 이 프로젝트의 중심이었다.

이 글은 당시 프로젝트 이력과 CV 기록을 바탕으로 2026년 11월에 정리했다.

## 행렬곱을 PE 배열로 옮기기

일반적인 행렬곱에서는 행과 열의 원소를 차례로 곱한 뒤 누적한다. **Systolic Array**에서는 이 연산을 여러 PE에 배치하고, 입력을 인접한 PE로 전달하면서 부분합을 계산한다.

{{figure /figures/journals/fpga-systolic-matrix-array.svg | 인접한 PE 사이에서 행렬 데이터가 전달되고 부분합이 누적되는 Systolic Array 개념도다. 실제 구현 크기나 메모리 배치를 나타낸 것은 아니다.}}

각 PE가 따로 데이터를 읽는 대신 인접 PE를 거쳐 값이 전달되도록 하면 반복되는 행렬 연산을 파이프라인 형태로 구성할 수 있다. 다만 입력이 서로 어긋나 도착하면 연산 결과도 틀어지므로, **데이터가 이동하는 시점과 각 PE의 연산 시점**을 맞춰야 했다.

## 초기 지연과 결과 생성 시점

배열에 처음 데이터를 넣었을 때 모든 PE가 곧바로 결과를 만드는 것은 아니다. 입력이 배열 내부로 전달되는 시간과 마지막 결과가 나오는 시점까지 고려해야 한다.

이런 초기 지연과 결과의 유효 시점을 다루면서, 하드웨어 병렬 처리의 핵심이 PE 개수를 늘리는 일만은 아니라는 것을 배웠다. 데이터를 공급하고 결과를 회수하는 경로가 같이 맞아야 가속기가 의미 있게 동작한다.

## 이후 CNN 가속기로 확장한 경험

이 프로젝트에서 다룬 것은 **행렬곱의 하드웨어 데이터 흐름**이었다. 같은 해 하반기에 개발한 [Bit-Shift CNN 가속기](/projects/bit-shift-cnn-accelerator-zynq/)에서는 IM2COL, Quantization, BRAM Controller, PS/PL 연동과 같은 더 넓은 시스템 설계가 필요했다.

두 프로젝트는 연결돼 있지만 동일한 작업은 아니다. 처음에는 Systolic Array 자체를 구현했고, 이후에는 그 연산 구조를 실제 CNN 추론을 위한 가속기 안에 통합했다.

## 구현 범위

2024년 프로젝트 기록으로 확인되는 결과는 **FPGA에서 Systolic Array 행렬곱 가속기를 구현했다는 것**이다. 이 초기 프로젝트의 별도 처리량·자원 수치가 없어 CNN 졸업프로젝트의 성능 결과를 가져와 쓰지는 않았다.

처리 요소의 동작과 데이터 전달을 클럭에 맞춰 구성한 경험은 이후 Zynq PS·PL 기반 시스템을 설계하는 바탕이 됐다.
